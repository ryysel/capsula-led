# Развёртывание capsula-led

Пошагово: от проверки колонки до автозапуска и диагностики. Всё выполняется
по ADB, перепрошивка не нужна, все файлы лежат в оверлее и удаляются одной
командой.

## Что понадобится

- VK Капсула 2019 с root-доступом по ADB (jailbreak). Проверено на прошивке
  44.90.
- Компьютер с `adb` и кросс-компилятором `aarch64-linux-gnu-gcc` (или Docker).
- Одна перезагрузка колонки — только чтобы проверить автозапуск. Для самой
  установки она не нужна.

## Шаг 1. Проверить колонку

```sh
adb devices
adb shell 'grep ^Uid: /proc/self/status'      # должно быть Uid:	0
adb shell 'cat /proc/device-tree/compatible'  # должно содержать rockchip,rk3308
adb shell 'ls -l /dev/led_multi_ctrl'         # устройство кольца
```

Если `Uid` не `0` или нет `/dev/led_multi_ctrl`, это не взломанная Капсула
2019 — дальше идти нет смысла. На Мини и других колонках VK другая карта
каналов, этот код их не поддерживает.

На этом firmware **нет** `id`, `sed`, `awk` и `install` — в командах ниже
используются только `grep`, `cut`, `cp`, `chmod`.

## Шаг 2. Собрать

```sh
git clone https://github.com/ryysel/capsula-led.git
cd capsula-led
./build.sh
```

`build.sh` делает статический бинарник: на колонке glibc 2.33, и статическая
сборка не зависит от версии библиотек.

Если кросс-компилятора нет:

```sh
docker run --rm -v "$PWD":/w -w /w debian:bullseye \
  bash -c 'apt-get update && apt-get install -y gcc-aarch64-linux-gnu && ./build.sh'
```

## Шаг 3. Скопировать на колонку

```sh
adb push capsula-led          /data/local/tmp/capsula-led
adb push etc/S98capsula-led   /data/local/tmp/S98capsula-led
adb push install.sh           /data/local/tmp/install.sh
```

## Шаг 4. Установить

```sh
adb shell sh /data/local/tmp/install.sh /data/local/tmp/capsula-led
```

Установщик:

1. копирует бинарник в `/data/overlay/upper/usr/bin/capsula-led`;
2. копирует init-скрипт в `/data/overlay/upper/etc/init.d/S98capsula-led`;
3. добавляет строку автозапуска в копию обёртки
   `/data/overlay/upper/usr/bin/voice-agent.sh`;
4. запускает демон и проверяет, что процесс жив.

Ожидаемый вывод заканчивается на `INSTALL_PASS`. Часы должны появиться на
кольце в течение пары секунд.

> **Почему именно в `/data/overlay/upper`, а не в `/usr/bin`.** Корневая ФС
> здесь squashfs, а сверху overlayfs. Запись через объединённый путь может не
> доехать до верхнего слоя и после перезагрузки откатиться на старую версию.
> Проверять после перезагрузки надо `md5sum`, а не `ls`.

## Шаг 5. Проверить, что часы живут

```sh
adb shell 'ps | grep capsula-led'
adb shell 'logread | grep capsula-led'
```

В журнале видно переходы `clock` ↔ `stock` и разобранные маркеры
`voice-agent`. Проверка «уступает ли кольцо»: скажите Марусе что-нибудь —
во время ответа кольцо должно анимироваться штатно, а примерно через секунду
после ответа вернуться к часам.

## Шаг 6. Автозапуск

Отдельного шага нет: установщик уже добавил хук. Но проверить его стоит
перезагрузкой.

```sh
adb reboot
# после загрузки
adb shell 'logread | grep capsula-led'
adb shell 'ps | grep capsula-led'
```

Ожидаемо: через ~10 секунд после старта `voice-agent` в журнале появляется
`daemon started`, затем `clock`.

### Почему хук в обёртке, а не отдельный init-скрипт

`rcS` разворачивает glob `/etc/init.d/S??*` **до** того, как
`S23overlayfs.sh` смонтирует оверлей. Поэтому новый `S98capsula-led` в
оверлее никогда не попадёт в список автозапуска. Зато `voice-agent.sh`
вызывается уже после монтирования (`S97voice-agent.sh`), поэтому хук живёт
там:

```sh
( sleep 10; /etc/init.d/S98capsula-led start ) >/dev/null 2>&1 &
exec voice-agent "$@"
```

`sleep 10` нужен, чтобы не спорить со стартовой анимацией колонки.

## Настройка

Всё в `src/ledctl.c`, потом пересобрать и повторить шаги 3–4.

- **Яркость по времени суток** — функция `schedule_pct()`:

  | Время | Яркость |
  |---|---|
  | 08:00–20:00 | 100 % |
  | 20:00–23:00 | 70 % |
  | 23:00–08:00 | 30 % |

- **Цвета** — в `clock_frame()`: заливка минут (бирюза `0,200,170` → синий
  `0,60,220`), метка часа (янтарь `255,110,0`), верхний индикатор
  (AM `0,0,60`, PM `90,35,0`).
- **Частота кадров** — `now - last_render >= 5` в `daemon_loop()`
  (по умолчанию раз в 5 секунд).
- **Предохранитель от залипания** — `now - last_change >= 40` там же.

Яркость по датчику невозможна: BH1750 на этой ревизии читается как `0` в
освещённой комнате и даёт 20–45 только от фонарика в верхнюю панель, а
`bh1730fvc` не отвечает на i2c и драйвера в ядре не имеет. Поэтому расписание.

## Диагностика

| Симптом | Что проверить |
|---|---|
| Кольцо тёмное, часов нет | `ps \| grep capsula-led`; вручную `capsula-led clock 20`; есть ли `/dev/led_multi_ctrl` |
| Часы были и пропали навсегда | последний маркер в `logread` — «занято»; `logread \| tail -40`; помогает `init.d/S98capsula-led restart` |
| Часы мигают или дёргаются | кто-то ещё пишет в кольцо: `capsula-led watch 10` |
| После перезагрузки часов нет | хук не попал в обёртку: `tail -5 /data/overlay/upper/usr/bin/voice-agent.sh` |
| Сегменты светятся не там | `capsula-led test`, затем `capsula-led map` — сверить карту |
| Демон умирает после выхода из adb | запускать только через init-скрипт (`start-stop-daemon`), а не `... &` |

Ручные команды:

```sh
capsula-led test              # перебрать 12 сегментов и верхний индикатор
capsula-led map               # записать в каналы 1..39 и прочитать sysfs
capsula-led watch 10          # показать, меняет ли кто-то кольцо
capsula-led clock 30          # часы на 30 секунд без демона
/etc/init.d/S98capsula-led restart
logread | grep capsula-led
```

## Удаление

```sh
adb push uninstall.sh /data/local/tmp/uninstall.sh
adb shell sh /data/local/tmp/uninstall.sh
```

Скрипт останавливает демон, удаляет бинарник и init-скрипт из оверлея и
убирает строку автозапуска из обёртки. Если в обёртке больше нет чужих
хуков, удаляется и сама копия — тогда после перезагрузки возвращается
стоковая.

## Приложение: как всё устроено

### Кольцо

Драйвер отдаёт 39 каналов через `/dev/led_multi_ctrl` и ioctl
`LEDS_MULTI_CTRL_IOCTL_MULTI_SET` (`_IOW('z', 0x01, …)`) — массив структур
`{trigger, delayed_trigger_ms, brightness, delay_on, delay_off}`. Для
статичного цвета `trigger = 1` (`TRIG_DEF_ON`), `brightness` = 0…255.

| Каналы | Что |
|---|---|
| 0, 1, 2 | верхний индикатор, R, G, B |
| `3 + 3i` | кольцо, пиксель `i`, зелёный |
| `4 + 3i` | кольцо, пиксель `i`, красный |
| `5 + 3i` | кольцо, пиксель `i`, синий |

Пиксель `0` физически на **9 часах**, индекс растёт по часовой стрелке,
поэтому 12 часов — это пиксель `3`.

Обратное чтение — `/sys/class/leds/led1…led36` (кольцо) и
`led37…led39` (верхний индикатор). Важно: записи `voice-agent` в эти
атрибуты **не видны**, поэтому по sysfs нельзя определить, кто сейчас владеет
кольцом. Отсюда и отдельный механизм определения простоя.

### Как определяется простой

`voice-agent` пишет в syslog небольшую машину состояний. Демон раз в секунду
читает `logread` и берёт **последнюю** строку-маркер:

| Строка | Смысл |
|---|---|
| `led animation loaded from …` | занято (кроме `ready.json`) |
| `WAITING_FOR_KEYWORD => PHRASE_IN_PROGRESS` | занято |
| `PHRASE_IN_PROGRESS => PHRASE_RESULT_PENDING` | занято |
| `SPEECH: start` | занято |
| `onSpeechPlaybackFinished`, `SPEECH: stop` | ответ закончился |
| `PHRASE_RESULT_PENDING => WAITING_FOR_KEYWORD` | ответ закончился (команды без озвучки) |

Возврат к часам — через 1 секунду после «конец», чтобы не спорить с
финальной анимацией. Если 40 секунд не приходит ни одной новой строки
(музыка, зацикленная анимация), срабатывает предохранитель и часы
возвращаются. На старте, пока маркеров ещё нет, часы включаются через 15
секунд.

Порядок строк берётся из позиции в буфере журнала, а не из меток времени:
часы на устройстве прыгают из-за `ntpd`, и в журнале встречаются строки с
временем «из прошлого». Фильтр по timestamp отбрасывал бы свежие события.
